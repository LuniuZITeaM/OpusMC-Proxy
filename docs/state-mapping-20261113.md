# 方块状态表兼容修复

用户遇到 `房间方块注册表不是 26.2，无法直接代理`。旧校验在上游状态表长度不等于内置 32366 时直接抛出这一异常。表长差异不足以确定上游版本，也不足以证明方块无法转换；此前“必须编号完全一致”的约束过强。

1.0.3 在收到 `states.list` 时，以状态名称和完整属性构造上游 ID → 客户端 26.2 ID 表。默认 `minecraft:` 前缀和属性顺序不影响匹配。只做准确名称匹配，不猜测其他版本的状态编号。

映射应用于二进制区块调色板、`block`、`blocks`、falling_block 实体的 spawn data，以及 LEVEL_EVENT 2001（方块破坏）、3008（刷扫完成）的 data。其他实体 data 与事件 data 不是方块编号，保持其原有含义。区块的空气/液体数量和高度图在映射之后生成，缺失区块段仍补客户端空气，避免上游空气编号不同导致整片地形错误。

未知状态使用客户端石头，并明确记录数量和最多八个状态名称。它们不能保证外观或碰撞与上游一致。空表、非法条目、缺少空气、引用越界状态等错误仍拒绝处理。日志增加上游和目标表长度及映射模式，便于后续定位；不保存或打印个人凭据。

测试覆盖：不同长度/排列、属性顺序、命名空间、未知状态、非法表和越界；完整 32366 状态正序/逆序映射；区块映射后空气、液体和高度图；方块更新、效果和落沙实体。TCP/WebSocket 集成测试使用只有两个状态且顺序不同的上游表，验证仍可完成登录，并将上游状态 0（stone）编码为 Java stone（1）。

尚未取得失败会话的实际 `states.list`，也没有使用个人账号进行真实房间联调。因此修复针对已证实的表长拒绝及编号假设，不能据此断言上游具体版本或完整游戏兼容性。
