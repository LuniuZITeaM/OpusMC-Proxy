# 区块包尾部兼容修复（1.0.4）

用户在状态表映射修复后遇到 `Trailing bridge chunk bytes`。这一异常只会在区块已知字段解析完成、仍有剩余字节时出现；没有失败包本体，不能确定尾部属于预留填充还是新增字段。

重新下载官方 `47455601425408-v47877/js/net.js`，SHA-256 为 `25cb6167f26e7df172012776a8f932ba9aa2bd7af0bcac36cb0804be4f96c843`，与此前副本一致。其 `NetClient.onBinary` 对类型 2 读完区块段后直接返回；类型 1 从当前位置读取 256 字节生物群系，随后应用区块，没有检查输入是否到达 EOF。

旧代理额外强制 EOF，因而比网页拒绝更多数据。1.0.4 保留所有已知字段校验和 8 MiB 输入上限，允许已知前缀之后存在任意尾部。尾部仅记录长度，不尝试解释或拼接到 Java 包。每次连接、每种包类型只提示一次，避免区块流量刷屏。

回归测试覆盖区块和光照包的零/非零/256 字节尾部、输出与无尾部包逐字节相同、非法核心字段即使带尾部也仍拒绝。TCP/WebSocket 集成测试先发带尾部区块，再发带尾部光照更新，然后验证后续方块更新和聊天继续工作。必需字段的全部截断前缀测试继续保留。

没有使用真实账号抓取用户的失败数据包，故此修复是对已确认网页解析策略的对齐，不构成对尾部内容的协议定义。
